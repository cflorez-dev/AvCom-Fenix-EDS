🧪 Origin Dropdown Selector - Testing Guide

📋 Estructura HTML que genera AEM

Esta es la estructura que Universal Editor crea en el DOM cuando guardas la configuración:

<div class="origin-dropdown-selector block">
  <!-- Campo simple: label -->
  <div>
    <div>Label</div>
    <div><p>Origen</p></div>
  </div>
  
  <!-- Campo simple: defaultValue -->
  <div>
    <div>DefaultValue</div>
    <div><p>BOG</p></div>
  </div>
  
  <!-- ⭐ Campo CONTAINER: cities -->
  <div>
    <div>Cities</div>
    <div>
      <!-- Cada item es un JSON string en un <p> -->
      <p>{"label":"Bogotá (BOG)","value":"BOG"}</p>
      <p>{"label":"Medellín (MDE)","value":"MDE"}</p>
      <p>{"label":"Cali (CLO)","value":"CLO"}</p>
    </div>
  </div>
</div>
🔑 Punto Clave: Los items del container NO son objetos JavaScript, son strings JSON dentro de elementos <p>

🔄 Flujo de Procesamiento

  1. readBlockConfig() extrae los valores del DOM: 
    config = {
  label: "Origen",
  defaultvalue: "BOG",
  cities: [
    '{"label":"Bogotá (BOG)","value":"BOG"}',  // ⚠️ STRING
    '{"label":"Medellín (MDE)","value":"MDE"}',
    '{"label":"Cali (CLO)","value":"CLO"}'
  ]
}
  2. JSON.parse() convierte cada string a objeto: 
    cities = [
  { label: "Bogotá (BOG)", value: "BOG" },  // ✅ OBJETO
  { label: "Medellín (MDE)", value: "MDE" },
  { label: "Cali (CLO)", value: "CLO" }
]
  3. Validación y filtrado de items inválidos
  4. Búsqueda de ciudad por defecto usando el código (value)
  5. Render del componente Preact con los datos procesados

🧪 Casos de Prueba

✅ Caso 1: Configuración Completa

Config en Universal Editor:
- Label: "Origen de viaje"
- DefaultValue: "MDE"
- Cities:
  • Label: "Bogotá (BOG)", Value: "BOG"
  • Label: "Medellín (MDE)", Value: "MDE"
  • Label: "Cali (CLO)", Value: "CLO"

Resultado esperado:
✅ Dropdown muestra "Medellín (MDE)" por defecto
✅ 3 opciones disponibles en el dropdown

⚠️ Caso 2: DefaultValue No Existe

Config en Universal Editor:
- DefaultValue: "XYZ" (no existe en la lista)
- Cities: ... (BOG, MDE, CLO)

Resultado esperado:
⚠️ Warning en consola: "Default city code 'XYZ' not found"
✅ Usa primera ciudad (BOG) como fallback

🔧 Caso 3: Sin Ciudades Configuradas

Config en Universal Editor:
- Label: "Origen"
- DefaultValue: "" (vacío)
- Cities: [] (sin items)

Resultado esperado:
⚠️ Warning: "No cities configured. Using defaults."
✅ Usa 5 ciudades colombianas hardcoded

❌ Caso 4: Item con Datos Incompletos

Config en Universal Editor:
- Cities:
  • Label: "Bogotá (BOG)", Value: "" (vacío) ❌
  • Label: "", Value: "MDE" (vacío) ❌
  • Label: "Cali (CLO)", Value: "CLO" ✅

Resultado esperado:
⚠️ 2 warnings: "City item X is missing required fields"
✅ Solo "Cali (CLO)" aparece en el dropdown

📡 Event Listener (para integración)

Otros scripts pueden escuchar cambios del selector:

// Escuchar cambios de ciudad
document.addEventListener('origin-selected', (event) => {
  const { label, value, city } = event.detail;
  
  console.log('Nueva ciudad seleccionada:');
  console.log('- Label:', label);      // "Medellín (MDE)"
  console.log('- Value:', value);      // "MDE"
  console.log('- City Object:', city); // { label: "...", value: "..." }
});

// Leer valor actual desde data attributes
const container = document.querySelector('.origin-dropdown-selector-container');
console.log(container.dataset.currentValue);  // "MDE"
console.log(container.dataset.currentLabel);  // "Medellín (MDE)"

// Obtener lista completa de ciudades
const cities = JSON.parse(container.dataset.cities);
console.log(cities); // [{ label: "...", value: "..." }, ...]
